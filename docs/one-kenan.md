# One Kenan per machine

Kenan is one persistent identity with separate people's permission boundaries. Thread services share one core process; a person's private stores, consent and native execution UID remain their own.

The core's explicit principals, hashed credential bindings, registered scopes and unified grants decide each request. A service credential is not a human promotion. Native thread capability and original asking principal remain attached through transport proxies. Cross-person/root consultations use the declared root routes and actual audience; source placement never grants access to another person's private state.

Root consultation, memory and provider custody are integrations inside the same core, not additional agent/controller factories. Markdown owns duties and memory knowledge; adopted SQLite owns durable thread/effect identities and custody. Native runners can outlive transport/code replacement in their exact retained UID and pinned namespace without model restart.

Rooms retain their membership/router authority and transport service. Meet, telephone, local recognition, shared Live media and personal Remote/UI transports keep their own external-session lifetimes. The core does not convert those lifetimes into extra reasoning engines.

[Core host deployment](core-host.md) owns installation and conservation. [Core custody](core-custody.md) describes data views, namespace pins and retained resources. Host handbooks hold actual configuration, key custody and serving evidence. [Action journal](action-journal.md) owns accepted outbound effect receipts and publication into memory.

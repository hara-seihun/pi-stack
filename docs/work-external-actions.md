# Work-only canonical action interface

This is a bounded action view, not a general environment grant, folder unlock or personal profile. The owning router authenticates the registered local Unix account. Root-owned `/etc/pi-stack/work-actions.json` declares outbound `routes` keyed by account, each with an HTTP origin and root-only `capabilityFile`. An explicit `PI_STACK_WORK_ACTIONS_CONFIG` selects another absolute owning file. An absent standard configuration leaves existing routes unchanged; invalid explicit configuration fails closed.

The receiving canonical supervisor reads only `grants`: capability SHA-256, exact canonical `owner`, fixed work `scope` and `sourceEnvironment`. The secret is generated for this service boundary, never exported from a personal profile or sent in process arguments. Router forwarding is restricted to `/v1/work-external-actions`, has no redirect path, strips forged credentials, and never creates a general home/environment grant. That endpoint is unavailable through ordinary app proxying.

Allowed operations are `submit`, `inspect` by explicit ID, `claim`, one-shot `dispatch`, and `finish`. Listing, Life/memory access, reconciliation/retry/followup/recovery and global recipient/alias changes are outside this initial scoped grant. Underlying permission to send does not change. A capability binds the owning work account; submitted actor/owner/scope strings cannot enlarge it.

The existing canonical encrypted ActionStore owns all reservation decisions. A scope projection row is committed atomically with a newly created action in the same database, never a competing ledger or separate recipient namespace. Private and other-scope conflicts return only generic blocked status without IDs, payloads or state. Scoped inspections require that projection. Returned recipient identities are limited to those submitted in the work scope, not private aliases used internally for shared fencing. Owner/private and work contacts therefore still block each other when unresolved, without disclosing each other's purpose.

Current source is **not configured or deployed**. Canonical work effects remain unavailable until the owning host interface is provisioned and synthetic no-effect isolation, shared fencing and real scoped route acceptance pass. Fixture secrets/identities are synthetic. Host capability installation and release custody must follow the actual scoped grant; no personal token/profile copy or fallback ledger is an acceptable recovery.

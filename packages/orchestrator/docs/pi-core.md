# Pi engine and its child tree

[`openPiSession`](../src/cores/pi.ts) implements [`OpenCoreSession`](../src/cores/contracts.ts). It returns `command()` and `close()`, never an `AgentSession`. PiStack supplies the root's initial provider, model and effort in the existing argument list. Pi owns its sessions, tools, prompt assembly, compaction and recursive child delegation.

## Native runtime

[`pi-native.ts`](../src/cores/pi-native.ts) builds the same SDK services and resource loader as Remote's shared session entrypoint. Global and project extensions, AGENTS files, skills, prompt templates and normal coding tools remain enabled. Each child gets its own cwd-bound services and the same configured extension paths. The hosted-session retry settings apply to both roots and children. Account registration and account switching remain with the installed PiStack routing extension.

Root commands use the release-pinned `runSharedRpcMode` adapter generated by [`patch-shared-rpc.mjs`](../../runtime/patch-shared-rpc.mjs). Prompt, steer, follow-up, queue, model, thinking, compaction, bash, transcript and native session-navigation commands retain that protocol. The adapter also settles an extension-handled prompt that did not start a model run.

`get_state` reports aggregate `isStreaming`, `isCompacting` and `pendingMessageCount`. Pending count includes queued native messages and outstanding child work/result deliveries. `nativeIsStreaming` preserves the root's own SDK streaming state. The response also includes `core: "pi"`, `coreAgents`, `coreBusy`, `nativeSessionId`, `messageCount`, `lastAssistantMessage` and authoritative `treeComplete`, while retaining the usual native `sessionFile`. `treeComplete` also waits for pending runtime opens, result injection and settlement bookkeeping. The core withholds the root's `agent_settled` while children, queued messages or result deliveries remain outstanding.

`get_core_context` returns the current native system prompt, tool schemas and messages. It is an inspection snapshot, not a portable transcript or a promise that extensions will not transform the next model request.

## Child tools and operator wire

Every Pi agent receives these tools in addition to its normal tools:

- `core_delegate` takes `task`, optional `threadId`, `newThread`, `model`, `thinkingLevel`, `cwd` and `workspace`. `workspace` contains `repo` and an absolute workspace-pool `root`. An idle suitable child is reused unless `newThread` is set. Existing workers retain their model and effort. New children default to Astra and high effort, or accept a catalog alias or `provider/model`.
- `core_read` takes an agent ID and entry-based `offset` and `limit`. It reads messages and custom messages without a model call.
- `core_list` lists direct children, including settled children.
- `core_control` steers, queues follow-up input or aborts a descendant. A child cannot abort its own ancestor from inside a tool call, which would deadlock that ancestor's abort waiting for the tool to return.

The delegation policy is imported from the existing [Codex-derived policy](delegation-policy.md). Tool descriptions adapt Remote's existing descriptions. No additional behavioral system prompt is installed.

PiStack's observer commands are separate from the model-facing tools:

```json
{"type":"core_agents","id":"list"}
{"type":"core_agent_read","id":"read","agentId":"CHILD_ID"}
{"type":"core_agent_command","id":"stop","agentId":"CHILD_ID","action":"abort"}
{"type":"core_agent_command","id":"steer","agentId":"CHILD_ID","action":"steer","message":"Changed requirement"}
{"type":"core_agent_command","id":"context","agentId":"CHILD_ID","action":"get_core_context"}
```

Read returns `{agent, messages, entries, state}`. State contains the native identity/file, cwd, model and aggregate activity. The command endpoint accepts native command fields alongside `action`. A new `prompt` sent to an idle child becomes another owned work item with automatic result delivery. Steering or follow-up input to an idle child starts that continuation rather than leaving an unconsumed native queue. Native command failures produce a failed outer acknowledgement.

`core_agent` carries `{core, rootId, agent, nativeSessionFile, cwd, workId}`. `agent` follows `CoreAgent` in the shared contract. `core_child_event` carries `{core, rootId, agentId, parentId, event}` for every child event. Child events are never emitted as root assistant output. Root-native events remain on the ordinary wire. In ordinary sessions, a context observer emits `context_update {context}` after extension context transforms, including the current system prompt, active tool schemas and LLM messages. Child context updates use the same child-event envelope. The adapter does not create a portable activity log; the shared factory owns `CoreJournal` and `get_portable_conversation`.

## Durable ownership

A root's state directory contains `pi-tree.json`, `root.jsonl` and `children/CHILD_ID.jsonl`. An explicit `--session` can place the initial root transcript elsewhere. Native new-session/fork/switch operations update the recorded reference. PiStack must open only one engine owner for a root/state directory at a time.

The tree records parentage, native paths and IDs, model/effort, work receipts, workspace ownership and result delivery. Delegation identities derive from the parent's ID and tool-call ID, so repeating an accepted tool call does not create another worker. State changes use atomic replacement with file and directory sync. Native sessions persist before their first assistant response, including after session replacement.

Root prompt, steering and follow-up commands carry a stable `workId`. `pi-tree.json` keeps a hash and receipt for each dispatch before native submission. Repeated IDs acknowledge the owned work without inserting its request again; changed content under the same ID fails. On restart Pi continues its recorded root work through the same recovery path as its children. A host recovery handoff from a pre-core session either adopts a final assistant result or injects structured recovery data, not another copy of the user request.

A completed child result remains in the tree until the parent's native transcript contains its `core_child_result` receipt. On restart the core checks that receipt before delivering again. Interrupted work receives a structured `core_recovery` record in the same native session through the SDK's custom-message path. It does not create another Remote thread or resubmit the initial task as another user message. Children that are waiting for their own children remain owned until those results have been integrated.

`abort` clears native queues and stops the target's entire subtree. Abort and close invalidate pending prompt preflight, so a delayed preflight cannot start another model run afterward. Native session replacement also stops descendants before replacing their owner. `close()` closes all opened runtimes once and cancels active work; idle completed workers remain recorded. An unexpected process restart recovers work, while an explicit close does not restart cancelled work.

For a requested workspace, the engine calls `agent-workspace create` with a deterministic child-specific name. Reopen heartbeats the registered path rather than cloning again. Active workspaces receive a heartbeat each minute. The worker releases its workspace after committing and transferring custody. The engine does not claim custody or discard unmerged changes for it.

## Fleet context and accounting

`--orchestrator-context` goes through [`isolatedCoreContext`](../src/host/isolated-context.ts). The adapter uses that owner's settings and resource loader, registers its providers with the SDK, applies its exact tool allowlist, and echoes the accepted contract as `get_state.context`. It does not add the ordinary context observer to the isolated extension list. Core delegation tools are not active unless the isolated contract explicitly supplies and selects them.

The isolated-context owner changes process cwd and environment. This path belongs to a dedicated fleet worker process. The adapter lets isolated extensions see the scrubbed environment and keeps that environment for tool execution, rather than restoring credentials or Remote identity from the original options afterward.

With `PI_ORCHESTRATOR_CORE_USAGE=worker`, the usage logger does not register its ordinary assistant `message_end` accounting handler. The fleet worker accounts for those messages from the root/child event wire. Provider-operation calls to `recordModelUsage()` and `after_provider_response` meter-header handling remain enabled. Attribution reads the current session-local environment; native children retain the owning fleet run ID without inheriting its model pin.

## Portable import

[`pi-transfer.ts`](../src/cores/pi-transfer.ts) atomically seeds a new native session with the transferred conversation before opening the SDK. It never calls `prompt()` to replay that history. A transfer hash permits reopening the same imported generation without importing twice and rejects a different transfer into an occupied generation.

Pi messages remain native messages. Other engines' user messages with Pi-compatible text or inline-image blocks remain user messages. Their remaining records, including native-only image references, become visible custom history with the complete original record retained. Foreign tool calls and provider reasoning state therefore do not become executable Pi history. Imported agent records remain provenance in `core_transfer`; they do not resurrect another engine's children. Missing recorded native session files are errors, not an invitation to start an empty replacement session.

## Remote integration and boundaries

The native runtime supplies a session-local async environment with `PI_STACK_CORE_OWNS_CHILDREN=1`, `PI_STACK_CORE_AGENT_ID`, `PI_STACK_CORE_PARENT_ID` and `PI_STACK_CORE_ROOT_ID`. Bash receives that identity without changing the extension-provided PATH. Remote suppresses external `thread_delegate` and `thread_subagents` under the owns-children flag. It retains `thread_thinking` and `thread_read` for independent PiStack threads; this core's children use `core_read` and `core_list`. The external delegation endpoint accepts no new child work from a core-owned parent. Already running pre-core parents can finish their existing delegation workflow.

Child runtimes clear `PI_REMOTE_SESSION_ID`, `PI_REMOTE_CONTEXT_OWNER_PID` and `PI_REMOTE_MEETING_ID`. Reusing the root's Remote identity would write child context into the root's context mirror. Ordinary SDK resources remain available, but Remote meeting tools, meeting-instruction fetches and inline-image tags are not supplied to native children. Supporting those requires a core-aware Remote identity/context bridge, not a `createSession` call. PiStack observes child activity through the core event wire and can inspect its current context with `get_core_context`.

External tool effects are not transactional. A crash can interrupt a tool after its effect but before its result is persisted; recovery cannot promise exactly-once external effects. There is no additional child scheduler or admission policy in PiStack, and this adapter does not implement a new budget or concurrency limit. Read tools page by entries rather than character chunks. Close and abort await native cleanup and therefore inherit the SDK's cleanup behavior for third-party extension resources.

## Focused checks

From the repository root, after installing the locked dependencies:

```sh
node packages/runtime/patch-shared-rpc.mjs node_modules
node_modules/.bin/vitest run packages/orchestrator/tests/pi-core.test.ts packages/orchestrator/tests/pi-native.test.ts packages/orchestrator/tests/pi-core-usage.test.ts --maxWorkers=1
```

The tree fixtures cover recursive completion, idempotent delegation, child reuse, abort/close, restart recovery, result-receipt boundaries and operator acknowledgements. Offline SDK tests cover resource/tool discovery, native RPC commands, durable session replacement, import/reopen and isolated-context acceptance. An accounting fixture checks worker message suppression, provider-operation attribution and meter headers. They do not call a live provider. Remote integration, public deployment and both-host verification belong to the integrating release task.

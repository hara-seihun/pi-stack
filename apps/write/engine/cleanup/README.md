# Write cleanup

`clean(words, dictionary, context) -> {text, edits}` accepts committed ASR words (`w`, nullable `conf`, `alts` as strings or `{w,conf}` objects). Automatic dictionary substitutions require a finite alternative confidence in [0, 1]; unscored strings remain valid input but cannot authorize a substitution. A low-confidence primary may switch only to a dictionary-listed alternative within .12 of its own score. Explicit replacement rules do not require an acoustic score. The recognizer supplies geometric-mean local joiner support for each single-token alternative, not a calibrated word-correctness probability or a rescored phrase lattice; missing scores are never copied from the primary. `IncrementalCleaner(dictionary, context).update(newly_committed_words)` and `.finish(final_tail)` share this contract; create one session per dictation. Edits use half-open indices into the full source word stream, including deleted words.

A bounded source-constrained pass handles fillers, direct repetition, explicit self-repair markers, dictionary replacements, low-confidence dictionary alternatives, two-word cardinal numbers, spoken formatting commands and casing. A resident CPU punctuation model then inserts sentence boundaries, commas and question marks before final formatting. Neither stage generates content words. Explicit `new line`, `new paragraph`, `bullet point`, `comma`, `period`, `colon`, `question mark` and `exclamation mark` are formatting commands. Quotation commands support `quote … unquote`, `open quote … close quote`, `start quote … end quote`, and `begin quote`; `un quote` is also recognized as a closing cue. Bare `quote` without a closing cue stays prose, so `quote me a price` is not consumed. Quoted words bypass disfluency deletion/repetition/repair rules, but explicit punctuation commands still work within quotes. Smart quotation marks are spaced correctly, and terminal punctuation is placed before the closing mark without duplication.

Direct-speech quotations are also inferred conservatively after punctuation: speaker/reporting-verb introductions followed by clearly direct first-person speech, greetings, imperatives or inverted questions (`she said hello`, `he said I will be there`, `she asked can you fix that`). Quoted spans stop at an inferred/source sentence boundary. Indirect clauses (`that`, `if`, third-person reports), ambiguous nominal clauses and trailing `and then` narrative are left unquoted. Existing explicit quotations take precedence. This is source-constrained linguistic inference, not an extra model: the pinned punctuation model has no quote label. There is no reliable way to recover arbitrary unmarked quote boundaries from text alone. Quote insertion and spoken controls retain source-index edit receipts and survive streaming/forked finalization. Content words otherwise come from the transcript or explicitly configured dictionary. A replacement rule has precedence over generic casing.

A session revisits its unfinished sentence on each update; completed source sentences outside the 12-word lookbehind are finalized. Partials can change, while `finish` only receives and processes the final tail plus unfinished sentence. Treat ASR timestamps and confidence as supplementary; a recognizer returning `conf=None, alts=[]` is supported. The product does not instantiate or reload a model per dictation.

The engine loads `JointOnnxTagger(cleanup_model_dir)` once from the pinned [Write cleanup model release](https://github.com/hara-seihun/pi-stack/releases/tag/write-cleanup-model-v1); `deploy/write-engine` verifies the hashes in `cleanup/model.json` and supplies its immutable model directory. `clean(..., tagger=tagger)` and `IncrementalCleaner(..., tagger=tagger)` reuse that resident CPU ONNX session. It deletes source words tagged with probability ≥.925, except dictionary words, numerals and negations, preserving source indices in explicit edit receipts. The model has punctuation and case heads, but those are not applied: they failed to improve held-out end-to-end punctuation. Requirements already include `onnxruntime`, `numpy`, and `tokenizers`. On 249 DisfluencySpeech audio clips transcribed with pinned Nemotron, this reduces token errors from 1,190 to 857/5,228; punctuation F1 .483→.516, casing .590→.706. CPU ONNX p95 for full cleanup was 6.75 ms; 6-word incremental tail p95 was 7.88 ms. With neither tagger nor punctuator arguments, the pure function remains rules-only for tests and other callers.

## Punctuation

`OnnxPunctuator` uses the pinned `1-800-BAD-CODE/punctuation_fullstop_truecase_english` ONNX model and SentencePiece tokenizer in `../punctuation-model.json`. `deploy/write-engine` verifies both assets and links the resident engine's `punctuation-model` directory. It runs after deletions and dictionary replacements, in both live and speculative/CPU-shadow cleanup. Only punctuation labels at original word boundaries are applied; model decoding and truecasing are not used. Original words, names, numbers and spelling remain unchanged. Explicit ASR/spoken punctuation wins; list/formatting commands delimit inference, and identifiers, URLs and paths are never punctuated internally. Long dictations use bounded 256-position windows with overlap. One locked, two-thread CPU ORT session is shared across dictations.

On the same 249 real-ASR DisfluencySpeech clips, this source-preserving pipeline improves punctuation F1 from .516 to .581, with p95 full cleanup 40.69 ms. The normalized word stream is identical to deletion-only cleanup on every clip. Punctuation remains an inference, not a guarantee: total word-plus-format token errors are 871 versus 857 because some marks differ from the reference. Earlier candidate-text reconstruction scored worse and is not used. A multi-sentence dictation matching Hara's reported failure now separates the statement and ends `Can you fix that?`. Set `PI_STACK_TEST_PUNCTUATION_MODEL` to the pinned model directory to run the real-model integration cases in `test_punctuation.py`.

A measured five-branch resident Qwen3-0.6B GGUF edit-lattice scorer did not improve on this pass: held-out DisfluencySpeech token errors rose from 977 to 988/5,228, with p95 full-utterance scoring 113 ms and p95 3–8-word-tail scoring 63 ms when four punctuation branches were active. It is not installed on the product path; the experiment's C++/Python sources and reproducible receipts live under `/home/kenan/work/pi-stack-write/cleanup/scorer_probe/`. This result does not exclude a shared-prefix KV implementation with better proposals.

Evaluation data, benchmark script and measured limitations are in `/home/kenan/work/pi-stack-write/cleanup/REPORT.md`. Run the contract regressions from the Pi Stack root with `python -m unittest apps.write.engine.cleanup.test_cleanup -q`.

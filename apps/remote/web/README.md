# Shared Remote client

Browser and native clients authenticate at the bootstrap router before discovering endpoints. The web client owns account sign-in, person selection on key-based hosts, router sessions, and endpoint selection.

## Browser mount path

The same built frontend works at `/` or a directory such as `/pi-stack/`. [`app-path.ts`](src/app-path.ts) derives the mount from the document URL. Vite emits relative chunk and public-asset URLs. Pages, artwork, API bootstrap, downloads, Meet navigation and invitations stay under that mount. The manifest uses a relative start URL and scope. There is no Pi Remote service worker to register or a root worker to replace.

The ingress redirects `/pi-stack` to `/pi-stack/`, preserving the query string, then strips `/pi-stack` from every forwarded request. The router and supervisors continue to serve their normal root-relative routes. Do not add root API or asset aliases. There is no per-host build or browser base-path environment variable. HTML pages live directly under the mount, not at arbitrary SPA routes. See [deployment](../../../docs/deployment.md#browser-prefix-hosting).

Browser person selection, folder keys, sessions, endpoint selection, drafts, transcript caches and notification coordination are scoped by mount. Root installs retain their existing storage names. A different path starts with separate browser state and needs its own authentication. This separates deployments' state, not same-origin security authority.

Android still loads its bundled root-relative pages and uses its configured bootstrap URL, which may itself include a mount prefix. API URLs returned by the router remain relative to that bootstrap. Meet invitations use the bootstrap frontend, not the selected remote API prefix.

## Account sign-in

An OAuth-enabled router advertises `environment.authentication` in the public chooser as `{ type: "oidc", loginPath: "/v1/auth/login", label: "Sign in with Google" }`, with an empty person list. The client retains this host setting when authenticated environment responses omit it. The chooser request omits cookies, session headers and person hints.

Before using a saved session or asking for a key, browser bootstrap calls `GET /v1/auth/session` directly through `browserFetch` with `credentials: "same-origin"`. A successful `{ ok: true, user, session }` response replaces the selected person and enters the existing router-session and endpoint-discovery flow. A 423 opens account sign-in; a 404 means key-based authentication only when the public chooser did not advertise OAuth. Network errors, malformed sessions and unexpected statuses stay visible and can be retried. OAuth hosts never try saved keys or empty-key unlocks.

The main app, Meet and Voice share the account sign-in dialog. Its button navigates the whole page to the bootstrap mount plus `/v1/auth/login`. The callback sets an HttpOnly cookie and returns to the app; no token passes through the callback URL. A lost router session attempts cookie restoration again. API headers and authenticated download URLs keep the existing router-session protocol.

On these hosts the environment picker contains only authorized environments. The client also rejects direct person changes, including stale person choices saved by a key-based deployment. Android key-based hosts keep their existing unlock flow without a browser-cookie probe.

## Native bridge

`KenanRemote.getState()` returns `{ routerUrl: string }`, the credential-free bootstrap URL. There is no native endpoint selection, preparation, or SSH setup.

`syncSession({ user, session })` replaces the native notification monitor's authorization. `session` is the opaque router token. Clearing auth sends `{ user: "", session: "" }` and stops monitoring. The monitor discovers allowed endpoints at bootstrap using this session. Every poll carries `x-pi-remote-session`; `x-pi-remote-user` is only a hint. A 423 response stops monitoring until the web client supplies renewed authorization. `notifications({ request })` checks or requests notification permission.

The haptic, keepAwake, notificationTarget, notificationThread, checkAppUpdate and installAppUpdate methods retain their existing roles; `webReady` tells the shell that a downloaded web bundle booted. Notification targets contain person, endpoint ID and thread ID, never a credential.

## Router contract

Unauthenticated bootstrap `GET /v1/environment` supplies the person chooser. `fetchPersonChooser()` explicitly uses that route without a session, even while signed in. Ordinary authenticated environment requests use the selected endpoint. `POST /v1/unlock` sends `x-pi-remote-user` and `{ key }`; success supplies `{ ok: true, user, session }`. Persons without encrypted folders submit `{}` to mint a session. `GET /v1/environments` requires that session and supplies the authorized endpoint list. Endpoint `baseUrl` values are same-origin prefixes, with an empty prefix for local. Icons are asset names from `public/`, such as `house` and `cloud`.

Unlock, lock, lock-status and endpoint discovery always use bootstrap, regardless of the selected endpoint. API calls carry `x-pi-remote-session`. Download URLs may carry `session` only on router API URLs, never external links. Keys are stored under the selected person; router sessions live in tab storage. Changing person clears session and endpoint state. A lock or router restart requires reauthentication, using the stored folder key when available. Endpoint selection checks `health.environmentId` before committing the selection; a misrouted upstream reports an error rather than opening the wrong host.

API fetches reject redirects so custom session headers cannot follow a router response to an external origin. Meet invitations contain no router session; the router does not authorize a guest by accepting the host's person name.

## Environment and person picker

[`EnvironmentControl`](src/EnvironmentControl.tsx) renders one full-width dropdown in the Machine screen containing the current person's authorized environments and every other person from the bootstrap chooser. It has an accessible name but no visible label, icon, or separate person button. People load independently of authenticated environment discovery and remain selectable during environment failures or switching. Choosing an environment uses `KenanRemote.select` to verify its identity before reloading; choosing a person uses `PiRemotePerson.set` to clear the previous session and endpoint selection, leaving authentication to the existing unlock flow. Auth and person events refresh the environment list and invalidate stale results. Each error can be dismissed through the shared [`DismissibleError`](src/dismissible-error.tsx) without clearing the failure or removing the dropdown's Reconnect option. Reconnect retries discovery and shows any renewed failure.

## Dismissible errors

[`DismissibleError`](src/dismissible-error.tsx) imports its own [CSS](src/dismissible-error.css). Pass `message` as a string, or an empty/null/undefined value to remove feedback. Optional props are `dismissLabel`, `className`, `role`, `resetKey` for a new attempt with the same message, and `onDismiss` for server-owned errors. The default role is `alert`; background feedback uses `status`.

Server-owned errors carry an occurrence ID. The client posts it to `POST /v1/errors/:errorId/dismiss` and hides the message after the server acknowledges it. While saving, the button is disabled. A failed save keeps the original error visible with a retryable dismissal error. Server synchronization removes dismissed errors from every client, including inbox and thread summaries. Browser reloads and supervisor restarts retain dismissal.

The supervisor's `error_feedback` table owns acknowledgements. Repeated reports of the same unresolved error keep their ID; recovery, changed messages and new naming attempts create a new occurrence. A stale dismissal cannot acknowledge a newer occurrence or an error from another thread. Dismissal does not change execution state, retry policy, native history or work outcomes.

Client-only errors, such as upload and connection failures, still dismiss locally. Keep failure state and retry actions in the caller. Changed messages, changed reset keys, or clearing the message reset local dismissal. The dismiss button has a 44px touch target and a visible keyboard focus outline.

## Toasts

[`toasts.tsx`](src/toasts.tsx) exports `toast` for short app-wide notices and `ToastViewport`, mounted once in the authenticated shell. [`toasts.css`](src/toasts.css) owns their styling. Sonner dismisses a toast after 3 seconds by default, pauses its timer during interaction, and lets people dismiss it with the close button or a left/right swipe. Changing account or environment clears visible toasts. Toast dismissal never changes the operation or its recovery state.

Import `toast` from `./toasts` in a client component or module. Use `toast("Saved")`, `toast.error("Upload failed")`, or `toast("Closed chat", { action: { label: "Undo", onClick: restoreChat } })`. Pass an `id` to update an existing notice; `toast.dismiss(id)` removes it.

## Presentation

Each visible fact has one owner in the current view. Recognizable navigation, provider and model icons carry accessible names and hover titles rather than adjacent labels. Text-only controls remain where an icon would be ambiguous. Status uses coloured text, not a second status dot. A meter may pair its shape with one exact number; descriptions do not repeat that number.

Collapsed entries summarize their content. Opening an entry replaces its excerpt with the complete data rather than displaying both. Tool arguments, results, copy actions and original model context remain available. The inspector opens as a right sidebar, and the new-chat menu stays within the inbox column. Other modal sheets cover the underlying screen. Keyboard interaction, accessible names and distinct actions such as cancellation versus attachment remain separate from visual repetition.

## Optimistic actions

A pending mutation renders its successful result immediately. Keep the same layout and controls, with a small pending marker where needed. Do not introduce a second pending card, a banner or recovery buttons during a healthy request. Errors belong to the affected operation and can expose recovery actions after failure or an uncertain outcome.

Signal sends enter the normal transcript immediately, including attachments, with `sending` in the delivery footer. The composer clears at submission and stays available for another message. Each send keeps its request ID through HTTP responses and history updates, so the receipt replaces the pending message rather than appending another. A lost acknowledgement changes only that message to `unknown`, unless history already supplied a receipt. Check send status reuses its exact request; Use failed draft restores a confirmed failure without overwriting another draft. Neither path adds a second copy below the transcript. Removing a draft attachment hides it immediately and restores it with an error if removal fails.

## Chats and conversation

[`chats.ts`](src/chats.ts) gives AI and human chats distinct `ai:` and `human:` identities in one inbox. The stream reconciles complete AI session and messaging directories. Directory contacts appear only when `current` is true. A remote close clears the selected chat, while incoming messages never select a chat. Archived threads are not in client state: the picker loads `GET /v1/sessions/archived` when it opens, and a thread opened from the picker or a notification is held as `discovered` until the directory carries it.

[`Inbox`](src/features/chats/Inbox.tsx) groups chats as Needs you, Working and Quiet. It sorts AI threads by `attentionRank` from [`thread-status.ts`](src/features/status/thread-status.ts), then by recency; human conversations use their unread and backend state. The Workers status means a child is running, not merely that children exist. When the last local or fleet child settles, an idle parent returns to Idle through the session activity patch, even if the parent's own revision has not changed. Child existence belongs in the worker tree and inspector, not an inbox status chip. Search filters the inbox. Its archived-search action opens the picker with the query. There is no client or server ordering API.

The + picker opens below the inbox header, bounded to the thread-list column. It is nonmodal, so the conversation remains visible. It lists Personal, Home, Archived and configured messaging profiles. Personal and Home list models for a new chat. Archived restores the chosen conversation immediately without resuming held work. Messaging profiles list contacts and groups by most recent activity, including closed conversations and directory entries. Backend icons come from the plugin.

Model and messaging categories with at most eight choices show every choice without search. Larger categories show a search field and up to twenty results, initially ordered by recent activity or model use. Archived always has a search field, including when opened directly from an inbox query. Search covers the full category, not just the displayed twenty. Archived searches run on the server across all archived conversation roots. Models never used keep their configured order after recently used models; within each group the picker retains that order. Both the new-chat picker and the existing-thread Model selector group Fable and Astra under God intelligence (Super expensive), Opus and Sol under Smart models, and Luna and Bonsai under Cheap and fast. Unknown and custom models appear under Other models. Luna uses a moon icon. Messaging entries with equal activity use title order. An optional Open by address form remains available within messaging profiles. On phones the menu scrolls within the visible viewport. Back returns to categories; Escape closes the menu and returns focus to the + button.

Closing an AI chat stops it and its descendants; closing a human chat retains its history and receiving. Successful closes show an Undo toast and support Ctrl+Z or Cmd+Z, most recent first. Failed restores show a new toast with Retry Undo and retain the chat in undo history. Closing, swiping away or letting the toast expire does not clear UndoCloses history; keyboard undo remains available until the page reloads or changes person or environment. Text editors, drawing and dialogs keep their own undo. Restoring an AI chat unarchives it without restarting cancelled work. The backend decides when a closed chat returns.

Long press an AI thread row to open its six colour swatches. Right click or Shift+F10 on the focused row opens the same picker. A normal tap still opens the thread; scrolling cancels the long press. The chosen colour tints the left-hand icon, including emoji icons, with no separate colour circle or row ribbon. Selection, Escape, Back or an outside click closes the picker. The centre clear action restores the icon's original colours. Remote stores colour by thread ID in `thread_views`, so renaming, archiving and restarting do not lose it, and other clients receive it through session patches. Saving previews the icon colour immediately; a failed request restores the server colour and shows an error.

The transcript follows the bottom only while the reader stays there. Scrolling up even a few pixels preserves the reading position during streaming and finalization; Jump to latest opts back in. Browsers without native scroll anchoring use a saved visible-message position, including compensation when finalization replaces the live message.

Agent and messaging conversations use the same [`ChatMessage`](src/chat-message.tsx), [`ConversationView`](src/ConversationView.tsx), [`Composer`](src/Composer.tsx) and [`useChatDrawing`](src/chat-drawing.tsx). Source adapters supply author, content, attachments and available actions to the message renderer. Headers, copy controls, text layout, image previews, scrolling and drawing interactions have one implementation. Streaming agent replies use that same message renderer. Stable agent and Signal messages have a Reply action on the message or in its long-press/right-click menu. Signal groups keep a separate action on each message, not on the sender block. A selected reply appears above the composer with Cancel; sending passes its message ID as `replyTo`. Agent selections persist with the per-thread draft, and Signal selections remain with the mounted conversation draft. Quoted replies render from their stored sender and text, so they remain readable when the original is outside the loaded window. Clicking a quote scrolls to and highlights the original if it is loaded, otherwise the quote says it is not loaded. Streaming and unsaved messages cannot be reply targets. Signal text remains literal rather than being interpreted as agent Markdown; delivery receipts belong to messaging, and native context, tools, model settings and Stop belong to agents.

[`MessageReactions`](src/message-reactions.tsx) renders under each message, including each segment of a grouped human exchange. Only messages with a server-issued `identity` get controls; live answers and pending sends have none. A chip lists the people who used that emoji and toggles the current person's reaction; + opens common emoji choices and an input for another emoji. Escape returns focus to +; tapping outside closes the picker. The server marks projected local reactions with `own`, which matters for Signal because its sender IDs are Signal addresses rather than Remote usernames. The client sends `{ messageId: identity.id, emoji, remove? }` to `POST /v1/messages/reactions` and replaces the chips with the returned reaction list. Failed requests leave the existing chips intact and show a dismissible error beside them. The long-press menu, drawing and copy actions remain on the message itself.

A conversation transcript keeps every user and assistant message and puts each intervening stretch of agent work in one work card. The collapsed card summarizes its steps and shows the latest one. Expanding a card shows every entry in order: tool calls, thinking, system prompt and tool schemas. Tool arguments and result blocks appear once, preserving their original content and order. Expanded text steps replace their opening preview with the body. The header owns thread status and queue access; the current step owns the active tool name. The composer provides Stop, Resume or Send, with a delivery menu for queue, steer or hard steer. That menu lists alternatives to the current mode.

On desktop, a visible selected list row owns the thread title while the conversation header owns model and status. Filtering, collapsing or scrolling that row out of view restores the title to the conversation. Phone detail always shows its title. The information button is the sole inspector action.

Neither the Markdown renderer nor KaTeX is in the page at startup, and the inbox, Workers, Files and Machine screens need neither. [`markdown-engine.ts`](src/markdown-engine.ts) downloads markdown-it, texmath and the delimiter shim when the first `Markdown` component mounts; until they arrive a block shows its own source as escaped `.markdown-plain` text with its line breaks. [`math-engine.ts`](src/math-engine.ts) downloads KaTeX, its stylesheet and fonts when the first formula renders; until then formulas show as `.math-pending` monospace source. Either arrival re-renders every mounted Markdown block. Compiled formulas are remembered, so a streaming message does not recompile them on every chunk. A test with the vendor scripts already on `window` gets the renderer synchronously; anything asynchronous awaits `ensureMarkdown()`.

[`MessagingConversations`](src/Messages.tsx) owns messaging transport and per-chat drafts, not a separate message UI. It reloads active history on messaging-version changes, selection, or visibility, without polling the messaging listing. Locking or switching people remounts the client and clears messaging drafts.

The paintbrush opens white paper. Clicking an image, or focusing it and pressing Enter or Space, opens that image in the same editor for either kind of chat. Image attachments show the preview without a second filename/download link beneath it. The image editor has a Download action for the original file; non-image attachments keep their links. Opening an image copies its decoded preview to a draft-owned bitmap, without retaining the transcript's DOM node. Pointer frames copy a viewport-sized backing canvas and paint the active stroke, rather than resampling the original image and repainting every completed stroke each time. Pan, zoom, resize, undo and stroke completion rebuild that backing canvas. Inactive drafts release both viewport pixel buffers but preserve strokes; removing a draft closes its bitmap. Owned context and messaging image downloads request server attachment disposition, so Download also works from Android's cross-origin client. Each chat and source image keeps its own drawing draft. Cancel retains the draft; Attach uploads a PNG to the originating chat's attachments without sending it. Attach is disabled until a new drawing has a stroke; an existing background image can be attached unchanged. Send submits the attachment even without text. An upload failure keeps the editor and strokes available for retry; a successful retry clears the error. Both kinds of chat hide their composer and conversation header while drawing, then restore focus to the control that opened the editor.

## The stream

[`stream.ts`](src/stream.ts) holds one `POST /v1/stream` connection per client and parses `text/event-stream`. The client declares wanted resources and the revisions actually held in its bounded replica. The server sends generic `reconcile` frames, which the replica applies before passing complete typed snapshots to the app. Resource IDs are `state`, `messaging`, `dashboard` and `transcript:`, `live:` or `images:` followed by the thread ID. On a base mismatch the client forgets that resource and requests a full frame. `hello`, notifications, durable events and errors remain direct events; later bootstrap changes reconcile too. Subscription changes post to `POST /v1/stream/:streamId`; changes during connection post after `hello` instead of opening another connection. A 404 reconnects with the whole subscription. A complete `state` snapshot removes missing rows, including workers removed while disconnected. There is no long poll or old delta protocol.

Live answer and thinking text never enter the app's state. [`live-text.ts`](src/features/conversation/live-text.ts) is a small store the open conversation subscribes to, so the server's 33 ms frames re-render that conversation and nothing else: not the inbox, the worker tree or the tab badges. `Inbox` and its rows are memoized for the same reason.

A stream that sends nothing for 30 seconds is dead even when the socket is open, so a watchdog drops it. Reconnection backs off to five seconds and happens immediately on `online`, `pageshow`, `focus` and a return to visibility. Connection state drives the OFFLINE pill and the Reconnect action. Frames scoped to a session the person has left are dropped before the app sees them.

The subscription follows the route: the open thread, whether it is visible, the Machine screen only while it is showing, and live thinking only while the thinking card is open. Reopening a thread paints a resident snapshot before reconciliation completes. `notificationsAfter` carries the current environment's idle cursor, so its settlements ride this connection; other granted environments keep a 30-second poll of `GET /v1/notifications`. Voice opens its own stream with `{session, eventsAfter, viewing: false}` and consumes durable `events` and reconciled `live` snapshots.

## Transcript items

The supervisor derives ordered items from the model context: system prompt, tool schemas, user and assistant text, thinking blocks, and each tool call with its result. The stream reconciles the newest 60 heads initially. `transcriptFrom` asks it to include every head from the earliest explicitly loaded seq, so corrections to older visible heads arrive too. [`transcript-store.ts`](src/features/conversation/transcript-store.ts) retains the earlier pages and replaces corrected heads in the authoritative window. A new generation from compaction, a fork or tree navigation replaces the whole window and resets `transcriptFrom`.

Show earlier pages older heads through `GET /v1/sessions/:id/transcript`; a 409 carries the generation that replaced the one asked for, along with its newest window, and that window replaces what the client holds. After paging, the stream reconciles the loaded suffix, not only new items. An empty generation with no items means the thread has no captured context yet.

Canonical context images inside item text arrive as `/v1/sessions/:id/images/:hash` Markdown images; the renderer resolves those through the selected endpoint and router session, as tool-result image blocks are.

The newest item of a window carries its complete `body` inline when it is under 8 KB: that is the step a person opens first, so it renders whole without a request. [`ItemBodies.accept`](src/features/conversation/item-bodies.ts) takes those bodies as the window changes and writes them to the same cache the fetched ones use. Heads carry only what names a step — strings cut at 120 characters, arrays at five entries, an edit's `editCount` instead of its edits, no written file content and no delegated message — so [`tool-summary.ts`](src/features/conversation/tool-summary.ts) reads `editCount ?? edits.length` and shows the diff only once a body has arrived.

Returning to a thread paints its cached heads, loaded bodies and inline-image metadata synchronously, before any disk or network request. [`client-cache.ts`](src/client-cache.ts) owns this memory across all AI threads in the authenticated app. Thread snapshots retain the newest 200 heads, with a 32-thread, 8 MiB limit and a 30-minute idle lifetime. Immutable bodies have a separate 2,000-entry, 32 MiB budget. Both use access-ordered eviction from [`resource-cache.ts`](../shared/resource-cache.ts). Concurrent body requests share one promise even when navigation remounts the conversation. Locking or changing person discards the memory owner; environment switching reloads it. Persistent keys include person and environment.

The stream refreshes cached threads when selected. Memory and disk windows seed the replica with the hash of their exact held JSON, so a reload declares a real revision instead of discarding cached heads. An empty window or changed generation is authoritative. Archiving, remote removal and forking drop the cached thread. Cold openings use IndexedDB without allowing a late disk response to overwrite a newer stream frame. Pointerdown, unread arrival and selection never fetch a duplicate transcript window. Each thread batches its own disk writes, so switching threads cannot cancel another thread's pending save.

Bodies load on demand from `GET /v1/sessions/:id/items/:itemId`, addressed by content hash, when a step opens or a copy button needs the complete text. [`transcript-cache.ts`](src/transcript-cache.ts) keeps them in IndexedDB, never invalidated, bounded to 2,000 entries and 64 MiB with least-recently-used eviction. Disk windows retain at most 32 threads and 8 MiB. A metadata store tracks counts, bytes and access order, so writing one body no longer reads every cached payload, and reading one no longer rewrites it. Oversized entries stay out of the cache. The database upgrade builds metadata once for existing entries. Expanding a step still shows the exact model context, with nothing added or omitted: only delivery is lazy. A collapsed row shows the head's preview, and a step waiting for its body says so.

Live answers and thinking arrive as reconciled full text snapshots. Thinking streams only while the person has the card open: opening it subscribes, closing it or leaving the thread unsubscribes, and nothing about that choice is stored.

## Shell, inspector and machine

[`Shell`](src/app/Shell.tsx) has four hash-routed destinations: `#/chats`, `#/workers`, `#/files` and `#/machine`. Below 900px it shows one pane and a bottom tab bar. Detail screens have Back, and each navigation pushes browser history. At 900px and above it shows an icon rail, list pane and detail pane. [`Sheet`](src/app/Sheet.tsx) supports a modal view and a nonmodal right sidebar. The inspector uses the sidebar on desktop and phone, leaving part of the conversation visible. Queue uses the modal view. Phone inspector and queue routes end in `/inspector` and `/queue`, so Back closes them. [`system-back.ts`](src/app/system-back.ts) answers the Android shell's back gesture with the same order the back arrow uses and returns false when nothing is left to close.

[`InspectorSheet`](src/features/inspector/InspectorSheet.tsx) has Thread, Settings and Timeline tabs. Thread shows facts, controls, parent, workers and Debug, which contains Voice and Meet controls. Settings uses [`SettingsFields`](src/thread-settings.tsx). Timeline loads `GET /v1/sessions/:id/events`. Model, thinking, speed and bash-timeout controls remain available while a thread runs or holds queued messages. Model changes select the next execution without interrupting current work. Archived threads must be restored before editing.

Changing a setting selects its expected value immediately, with a small Saving label until the response arrives. A model change also updates its thinking and speed choices. A failed save restores the last server snapshot and reloads settings to reconcile a partially applied or unacknowledged write. Request identities prevent earlier loads from overwriting a pending selection.

The selected option uses the server's saved model identity, not a pooled account alias from a running provider request. Each thread mounts its own inspector state, so a late save response cannot replace another thread's settings. The open inspector refreshes when the thread revision changes. Failed settings and child-list loads retain a Retry button even after dismissing the error; a failed save leaves the controls available.

Machine uses one provider mark per plan card, one remaining value with pace, a quota-window description, and an optional 24-hour cache value. Coverage and unavailable readings are separate facts. Each provider's background governor is one cycle control showing its current and next mode. Configured actions are full-row switches. Android update progress appears in its action button rather than a second progress sentence.

## What loads when

The first paint is the shell, the inbox and the conversation; everything else is its own chunk, one per screen or feature, so opening one costs one request rather than six. `React.lazy` covers [`FilesScreen`](src/features/files/FilesScreen.tsx) with its tree and virtualizer, [`MachineTab`](src/features/machine/MachineTab.tsx) with the environment picker, notification control and app updater, [`WorkersTree`](src/features/workers/WorkersTree.tsx), [`InspectorSheet`](src/features/inspector/InspectorSheet.tsx), [`QueueSheet`](src/features/queue/QueueSheet.tsx), [`PasteTextDialog`](src/PasteTextDialog.tsx), [`MessagingConversations`](src/Messages.tsx) and the drawing editor behind [`useChatDrawing`](src/chat-drawing.tsx). The sheets and dialogs mount when they open rather than rendering closed, which is what keeps their chunks off the first paint.

The chat picker is split from its button: the inbox paints the `+` immediately through [`chat-picker-lazy.tsx`](src/chat-picker-lazy.tsx). Both the initial button and the loaded picker import [`chat-picker-trigger.css`](src/chat-picker-trigger.css), so its size and accent styling do not wait for the first tap. Activating it loads [`ChatPicker`](src/thread-start-menu.tsx), including archived search, the messaging directory and account linking. Inbox archive search uses its typed `open` handle to select Archived and retain the query through lazy loading. Focusing the button does not open it. Voice is the same shape: [`voice-lazy.ts`](src/voice-lazy.ts) publishes `window.PiRemoteVoice` without WebRTC, and the first mic toggle loads [`voice.ts`](src/voice.ts). The Voice and Meet pages import it directly, because there voice is the reason the page exists. `DELIVERY_LABELS` lives in [`delivery.ts`](src/features/queue/delivery.ts) so the composer's delivery menu does not pull the queue sheet into the first paint.

Measure with `npm run build`: the compress step prints the largest twins, and `assets/index-*.js.br` is the app chunk. Removing the blocking vendor scripts and splitting the screens took the first paint from about 174 KB to 93 KB brotli — the app chunk, React, the shared chunk, the stylesheets and, before, 45 KB of markdown-it, texmath and the shim. The app chunk itself went from 55.8 KB to 28.6 KB.

[`WorkersTree`](src/features/workers/WorkersTree.tsx) shows the worker hierarchy. Its Active filter keeps whatever is working, the ancestors above it, and the direct workers of anything working, so a thinking orchestrator shows the settled subagents it is reading rather than an empty node; All shows every live tree. [`FilesScreen`](src/features/files/FilesScreen.tsx) owns the full Files layout, with a bounded tree column on desktop and folder navigation on phones. Breadcrumbs name folders; the preview owns the selected filename, metadata and actions. Root shortcuts are deduplicated by destination. Direct paths use authenticated `GET /v1/files/info?path=…` to distinguish files, directories and errors before opening a preview. [`file-navigation.ts`](src/features/files/file-navigation.ts) owns path and shortcut rules. Text, Markdown, images and PDFs have previews, with Download, Copy path and Attach to current chat. [`MachineScreen`](src/features/machine/MachineScreen.tsx) shows plans, governors, actions, host usage, environment, notifications, app updates and owner errors. [`StatusPill`](src/features/status/StatusPill.tsx) renders status as text, shared by inbox rows, conversation headers, the worker tree and inspector.

## Local preview

Run `npm run dev --workspace=pi-remote` from the repository root. The workspace selects its own Vite version and proxies `/v1` to the local router. Authentication uses the normal person session. Keep the server in the foreground and stop it after the preview. The root dependency tree also contains Vite for other tools; invoking its binary directly does not select Remote's Vite and React plugin pair.

Run `bun test apps/remote/web/app-path.test.ts apps/remote/web/router-auth.test.ts apps/remote/web/router-client.test.ts apps/remote/web/oauth-client.test.ts apps/remote/web/meet-adapter.test.ts apps/remote/web/stream.test.ts apps/remote/web/transcript-store.test.ts` from the repository root. The stream test covers the parser, session filtering, replica revisions and selection during connection; the transcript test covers authoritative recent windows, generations, paging and a 409. The client test covers root and prefixed browser and Android bootstrap, initial authentication, token renewal, open-person sessions, endpoint identity checks, download round trips and external URL handling. The OAuth test covers root and prefixed mounts, cookie restoration over stale identities and saved keys, sign-in navigation, account-bound selection, session failures and recovery. The path test builds one frontend into a temporary directory and checks its pages, assets, fonts and manifest behind a prefix-stripping ingress.
